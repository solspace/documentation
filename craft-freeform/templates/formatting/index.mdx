# Formatting Templates

Formatting templates control how a Freeform form appears on your site. Start with a bundled template, customize a copy, or build your own Twig markup using Freeform's render helpers.

<LegacyReferenceRedirect targets={legacyAnchors} />

## Render Your First Form

<VerticalStepWrapper>
<StepMarkdown>
Open the form builder and choose a **Formatting Template** in the form's settings.
</StepMarkdown>
<StepMarkdown>
Save the form, then check its appearance in the builder's [Preview tab](../../forms/builder/preview.mdx). Try bundled samples with the Preview-only **Formatting Template** selector and choose a viewport size. Add your site's CSS or JavaScript under **Additional Preview Assets** when needed.
</StepMarkdown>
<StepMarkdown>
Add this to the Craft Twig template where the form should appear, replacing `contact` with your form handle:

```twig
{{ freeform.form('contact').render() }}
```

</StepMarkdown>
</VerticalStepWrapper>

The form uses the template assigned in the builder. A formatting template can be shared across forms, and changing that assignment does not require editing the page template.

Framework templates need their corresponding CSS on the page. Freeform 5.17+ bundled Tailwind 3 samples include compiled framework CSS through Freeform's asset loading. See the template family's guide below for setup and customization details.

### Formatting Template with Form Render<Badge type="recommended" text="Recommended" />

Use `form.render()` to render the assigned template. To choose a different formatting template for a particular instance:

```twig
{{ freeform.form('contact', {
  formattingTemplate: 'contact.twig'
}).render() }}
```

Create and register custom templates through [Template Manager](../../configuration/settings/template-manager.mdx#formatting-templates). Follow [Creating a Custom Formatting Template](../../guides/guide/custom-formatting-templates.mdx) to clone a sample and apply it to your forms.

For changes to classes, attributes, labels, or initial values, use [Template Overrides](./overrides.mdx) before replacing the template's markup.

## Accessibility<Badge type="feature" text="Improved in 5.17+" />

Freeform's bundled formatting templates include improvements for keyboard navigation and screen readers. The specific improvements vary by template and field type:

- **Accessible choice groups:** Tailwind 4 and daisyUI 5 templates use `fieldset` and `legend` for Checkboxes, Radios, Opinion Scale, Rating, and Cards fields. This associates the question with its available choices.
- **Linked instructions and errors:** Inputs reference their instructions and validation errors through `aria-describedby`. Invalid inputs use `aria-invalid="true"`, helping screen readers identify fields that need attention.
- **Keyboard-accessible controls:** Updated Tailwind templates keep visually hidden choice inputs available to keyboard users and screen readers. Visible focus indicators identify the selected control when navigating with a keyboard.
- **Success and error messages:** Success banners use `role="status"` and error banners use `role="alert"`, giving assistive technologies additional context for submission feedback.
- **Multi-page progress:** The current page is identified with `aria-current="step"` in templates with page progress indicators.
- **File upload feedback:** Updated Tailwind 4 upload controls associate their labels with the file input, show keyboard focus, and use a status region for selected-file messages.
- **Table and image markup:** Table field column headings use `scope="col"`. The Multipage All Fields review template identifies row headings and provides alternative text for uploaded image previews.
- **Decorative icons:** Updated decorative icons are hidden from screen readers so they do not distract from labels and messages.

:::warning
Most existing sample formatting templates in Freeform 5 retain their original HTML structure to avoid breaking layouts and custom styles. Accessibility changes such as replacing field containers and labels with `fieldset` and `legend` will be introduced for these templates in Freeform 6. Newer templates, including Tailwind 4 and daisyUI 5, already use this markup for supported choice fields.
:::

### Focusing Validation Errors

Enable **Focus First Error After Submit** in the form's processing settings to move keyboard focus to the first visible field with an error after validation fails. If there are no field errors, focus moves to the form's error message.

### Custom Formatting Templates

Existing copies of formatting templates do not automatically receive updated Twig markup or copied styles. Compare your custom template with the latest bundled version and bring across the relevant changes, including supporting CSS.

When customizing, preserve label associations, instruction and error IDs, ARIA attributes, and keyboard focus styles. Prefer Freeform's render helpers where practical, and retain the generated attributes when rendering inputs manually.

These improvements provide a stronger starting point for accessible forms. The finished form's accessibility also depends on its labels, instructions, content, styling, and custom controls.
