# Connecting Integrations

Use the form's **Integrations** tab to enable connections and map fields for that form. Only connections already configured in [Freeform Settings](../../configuration/settings/index.mdx) appear here.

## Enable an Integration for a Form

<VerticalStepWrapper>
<StepMarkdown>
Configure and save the connection in **Freeform → Settings → Integrations**. See the [integration directory](../../integrations/index.mdx) for service-specific instructions.
</StepMarkdown>
<StepMarkdown>
Open the form's **Integrations** tab and select the configured connection in the left column.
</StepMarkdown>
<StepMarkdown>
Turn on **Use integration for this form**, then configure the available settings, field mappings, and conditions in the right column. Save the form.
</StepMarkdown>
</VerticalStepWrapper>

## Captchas

Enable the configured **reCAPTCHA**, **hCaptcha**, or **Cloudflare Turnstile** connection for the form, then review its available settings.

Please see the [Spam Protection](../spam-protection.mdx) documentation guide for more information about this feature.

## CRM & Email Marketing<Badge type="pro" text="Pro" />

Select the configured connection and enable it for the form using the steps above. Available settings and field mappings differ between integrations.

:::info
If a previously mapped field has been deleted, its dropdown will be yellow and display **Mapped field no longer exists**. Select another field to restore the mapping, or choose **Do not map this field** to clear it.
:::

### Conditional Rules<Badge type="feature" text="New in 5.12+" /> {#crm-conditional-rules}

Add conditional logic to your CRM and Email Marketing integrations to control **when** submission data is sent. Create rules based on other field values (e.g., send only if _Subscribe_ is checked or if _Country_ is `US`).

## Payments<Badge type="pro" text="Pro" />

If the **Stripe Payments** integration is available, click on it in the left column. Once loaded in the right column, toggle the **Use integration for this form** switch ON and proceed to configuring settings and field mapping as necessary. You will also need to add a [Stripe Payments](../fields/stripe-payment.mdx#stripe-payment) special field to the form layout.

See the [Stripe Payments](../../integrations/stripe-payments.mdx) guide for complete setup.

[Mollie](../../integrations/mollie.mdx) is also available. It redirects the submitter to a Mollie-hosted payment page and does not require a Mollie field in the form layout.

## Elements<Badge type="pro" text="Pro" />

This feature allows you to connect and map Freeform submission data to other Craft Elements such as [Craft Entries](https://craftcms.com/docs/5.x/reference/element-types/entries.html) and [Craft Users](https://craftcms.com/docs/5.x/reference/element-types/users.html). The possibilities are endless when you consider that it essentially allows you to easily create complex user registration forms or accept guest submitted content that maps to Craft entries for further management by site admins for publishing... or whatever else you can dream up!

Select the configured Element connection and enable it for the form using the steps above, then configure its settings and field mappings.

Please see the [Elements](../../integrations/elements.mdx) documentation for more information about this feature.

## Google Tag Manager<BadgeGroup><Badge type="lite" text="Lite" /><Badge type="pro" text="Pro" /><Badge type="feature" text="Improved in 5.17.3+" /></BadgeGroup> {#google-tag-manager}

Enable [Google Tag Manager](../../integrations/google-tag-manager.mdx) to push an event to the data layer once after a completed, successful **AJAX submission**. Validation errors, failed submissions, intermediate pages, and submissions identified as spam do not trigger it.

- **Event Name** - the event pushed to the data layer, such as `generate_lead`. If empty, Freeform uses `form-submission`.
- **Event Parameters**<Badge type="feature" text="New in 5.17.3+" /> - click **Add parameter** to map a custom parameter name to a non-personal choice, numeric, or hidden field value. Mappings are specific to each form. `form_name` is included automatically.
- **Container ID** - set this in the main integration settings only if you want Freeform to load GTM. Leave it blank when your website already loads GTM.

<Photo
  img={require('@site/static/img/craft/freeform/v5/integrations/gtm-event-mappings.webp')}
  alt="Google Tag Manager form settings with insurance_type and office_location field mappings"
  style={{ width: 1000, maxWidth: '100%', height: 'auto' }}
/>

:::warning Personal data
Never map names, contact details, addresses, message contents, or other personal data, including values stored in hidden fields or options.
:::

Configure a matching Custom Event trigger and GA4 Event tag in GTM using your existing Google tag. See the [GTM setup guide](../../integrations/google-tag-manager.mdx) for mapping limits, tag configuration, success/failure testing, and [JavaScript customization](../../integrations/google-tag-manager.mdx#customizing).

## POST Forwarding<Badge type="pro" text="Pro" />

This allows your forms to automatically submit an extra POST to pass off submission data to an external API URL upon successful submit and validation of a form. This option is available for simpler and/or limited integrations as an alternative to our traditional [Email Marketing](../../integrations/index.mdx) and [CRM](../../integrations/index.mdx) integrations.

- **URL** - if you need to have the POST data of this form submitted to an external API, provide that custom URL here.
- **Error Trigger** - provide a keyword or phrase Freeform should check for in the output of the external POST URL to know if and when there's an error to log, e.g. `error` or `an error occurred`.
- **Include Uploaded Files** - if files are present in the form submission, they will be attached to the payload and sent as multipart form data.

Please see the [POST Forwarding](../../integrations/post-forwarding.mdx) documentation for more information about this feature.
