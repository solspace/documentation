# JavaScript Plugin<Badge type='feature' text='Improved in 5.17+' />

Freeform's JavaScript plugin handles AJAX submissions and client-side features such as conditional rules, date pickers, table fields, CAPTCHA, and Stripe payments. Additional scripts are loaded as needed for the fields and integrations used by each form.

Use the options and events below to customize or extend this behavior.

:::info
In Freeform 5.17+, the default AJAX renderer uses compatible formatting templates' banner and field-error styling. Custom JavaScript is optional for styling these elements.

Success and error messages can also be configured in the form builder. Use JavaScript overrides or rendering events when you need additional control. See [AJAX Forms](../templates/ajax.mdx) for examples.
:::

## Getting Started

Use the `freeform-ready` event to override options during form initialization. Listen on `document` to apply changes to all forms, or on a specific form element to target only that form.

<Tabs>
  <TabItem value="plugin-ready-all" label="All Forms" default>
    ```js
    document.addEventListener('freeform-ready', (event) => {
      event.options.showProcessingText = true;
      event.options.processingText = 'Submitting...';
    });
    ```
  </TabItem>
  <TabItem value="plugin-ready-specific" label="Specific Form">
    Assign the form a unique ID and register your listener after its markup:

    ```twig
    {{ freeform.form('myFormHandle', {
      attributes: {
        id: 'my-form'
      }
    }).render() }}

    <script>
      const form = document.getElementById('my-form');

      form.addEventListener('freeform-ready', (event) => {
        event.options.showProcessingText = true;
        event.options.processingText = 'Submitting...';
      });
    </script>
    ```
  </TabItem>
</Tabs>

Replace `myFormHandle` with your form's handle and ensure `my-form` is unique on the page.

The `freeform-ready` event provides:

- `event.form` — the form element.
- `event.freeform` — the Freeform plugin instance.
- `event.options` — an object for supplying option overrides.

See [Plugin Options](#plugin-options) for the available settings.

## When to Call Your Custom Scripts

Register your event listeners before Freeform initializes the form. A listener added after initialization will not receive the earlier `freeform-ready` event.

Document-level listeners can be registered before the form markup exists. Listeners attached directly to a form require that element to exist first, so place them after the form markup.

Forms added dynamically to the page are automatically detected and initialized by the loaded Freeform plugin. Each newly initialized form also dispatches `freeform-ready`.

## Loading Freeform JS Manually<Badge type="feature" text="Improved in 5.5+" />

To control where Freeform's assets appear in your template, set **Script Insert Location** to **None** under [Form Behavior](../configuration/settings/form-behavior.mdx), then use the helpers below.

Manual loading controls where Freeform's assets are inserted. The loaded plugin still handles form initialization and its configured behavior, including AJAX submissions.

| Helper | What it loads |
|---|---|
| `freeform.loadScripts([...])` | Assets selected by their script identifiers. |
| `freeform.loadFreeformPlugin()` | The main Freeform JavaScript and CSS files. |
| `freeform.loadFreeformPluginJs()` | Only the main JavaScript file. |
| `freeform.loadFreeformPluginCss()` | Only the main CSS file. |
| `freeform.loadFormSpecificScripts(form)` | Additional scripts and styles required by the specified form, such as CAPTCHA and JavaScript Test assets. Accepts a Freeform form object or form handle. |

Load the main plugin once per page and include the additional assets needed by the forms on that page. These helpers generate the published asset URLs for you.

Use `loadScripts()` when you want to explicitly select the assets to load:

Use this approach to load the main plugin together with the additional assets required by a particular form:

{{ freeform.loadFreeformPlugin() }}
{{ freeform.loadFormSpecificScripts(form) }}

Replace `myFormHandle` with your form's handle. Place these calls after the form markup, typically near the end of the page.

## Form Events

Freeform dispatches events that let you customize form initialization, submission, and rendering.

Listen on `document` to handle events from all forms, or on a specific form element to target only that form. Each event includes:

- `event.form` — the form element.
- `event.freeform` — the Freeform plugin instance.

Additional properties are listed under each event below.

### Plugin Initialized: `freeform-ready`

Fires during initialization, before Freeform applies your option overrides and completes the form's setup.

Use `event.options` to supply overrides for the [Plugin Options](#plugin-options). Register your listener before the form initializes.

#### Additional Property

- `options` — an object for supplying option overrides.

```js showLineNumbers
document.addEventListener('freeform-ready', (event) => {
  event.options.showProcessingText = true;
  event.options.processingText = 'Submitting…';
});
```

Success and error messages can also be configured in the form builder. In Freeform 5.17+, compatible formatting templates provide styling for the default AJAX renderer, so JavaScript overrides are optional.

### On Submit: `freeform-on-submit`

Fires before Freeform submits the form, for both AJAX and regular submissions. Use it to modify field values, perform additional checks, or register asynchronous tasks.

Call `event.preventDefault()` to stop the submission.

#### Additional Properties

- `isBackButtonPressed` — whether the submission was triggered by the multi-page form's Back button.
- `addCallback(callback, priority = 0)` — registers a callback that Freeform waits for before submitting.

The following example checks a checkbox field with the handle `terms`. Replace that handle and the validation logic to match your form.

```js showLineNumbers
const form = document.getElementById('my-form');

form.addEventListener('freeform-on-submit', (event) => {
  if (event.isBackButtonPressed) return;

  const terms = event.form.querySelector('input[name="terms"]');

  if (terms && !terms.checked) {
    event.preventDefault();
    alert('Please accept the terms before submitting.');
  }
});
```

#### Asynchronous Submission Callbacks

Use `event.addCallback()` when a check or task must finish before the form submits. Freeform pauses submission while the registered callbacks run.

- Return `true` or nothing to allow submission to continue.
- Return `false` to stop submission.
- Callbacks run sequentially, from lowest to highest priority.
- The default priority is `0`; negative priorities run before it.

This example calls a custom validation endpoint that returns an object such as `{ "valid": true }`. Replace the endpoint and response handling with your own implementation.

```js showLineNumbers
const form = document.getElementById('my-form');

form.addEventListener('freeform-on-submit', (event) => {
  if (event.isBackButtonPressed) return;

  event.addCallback(async () => {
    try {
      const response = await fetch('/my-validation-endpoint');

      if (!response.ok) {
        throw new Error(`Validation request failed: ${response.status}`);
      }

      const result = await response.json();

      if (!result.valid) {
        alert('Please review your entries before submitting.');
        return false;
      }

      return true;
    } catch (error) {
      console.error('Unable to validate the submission:', error);
      alert('Unable to validate your entries. Please try again.');
      return false;
    }
  }, -100);
});
```

Client-side checks supplement server-side validation. Validate any requirements that must be enforced on the server as well.

### On Reset: `freeform-on-reset`

Fires after Freeform resets the form following a completed, successful AJAX submission. Use it to reset custom interface elements or other client-side state.

This event is skipped when form resetting is disabled or Freeform redirects before resetting the form. It is a notification after the reset; preventing this event does not undo the reset.

```js showLineNumbers
document.addEventListener('freeform-on-reset', (event) => {
  console.log('Form reset:', event.form);
});
```

To detect resets triggered outside Freeform's AJAX handling, listen for the form's native `reset` event instead.

### Handle Submission Actions: `freeform-handle-actions`

Fires when an AJAX response contains pending actions that require additional processing, such as payment actions.

This event concerns front-end submissions, not saving a form's configuration in the form builder. Freeform's integration scripts handle their supported actions automatically.

#### Additional Properties

- `response` — the parsed response object.
- `actions` — the actions returned in the response.

This event is not cancelable.

```js showLineNumbers
document.addEventListener('freeform-handle-actions', (event) => {
  console.log('Pending submission actions:', event.actions);
});
```

### Before Sending an AJAX Request: `freeform-ajax-before-submit`

Fires after Freeform prepares the submission data, but before it sends the AJAX request.

Use this event to modify the outgoing `FormData`. Call `event.preventDefault()` to stop the request from being sent.

#### Additional Properties

- `data` — the `FormData` containing the submission values.
- `request` — the `XMLHttpRequest` object, before it has been opened or sent.

```js
document.addEventListener('freeform-ajax-before-submit', (event) => {
  event.data.set('myCustomValue', 'example');
});
```

:::info
The request has not been opened when this event fires, so you cannot call `event.request.setRequestHeader()` here.
:::

### Before Processing an AJAX Response: `freeform-before-ajax-success`

Fires after Freeform receives an HTTP 200 AJAX response, before it processes the result.

Despite its name, this event also fires when the response contains validation errors or pending actions. Check the response properties before treating the submission as successful.

#### Additional Properties

- `request` — the `XMLHttpRequest` used for the submission.
- `response` — the parsed response object.

```js
document.addEventListener('freeform-before-ajax-success', (event) => {
  const { success, finished } = event.response;

  if (success && finished) {
    console.log('A completed submission is ready to be processed.');
  }
});
```

This event is cancelable. Calling `event.preventDefault()` stops Freeform's remaining response handling, including rendering feedback, replacing form HTML, processing pending actions, and updating the form payload.

Canceling this event does not undo the request or any submission already processed by the server. Use it when your code will take responsibility for handling the response.

For changes limited to success or error markup, use the rendering events documented below instead.

### After a Successful AJAX Submission: `freeform-ajax-success`

Fires when Freeform processes a successful AJAX response. For multi-page forms, this can mean advancing to the next page rather than completing the submission.

Check `event.response.finished` before running code intended for a completed submission.

#### Additional Properties

- `request` — the `XMLHttpRequest` used for the submission.
- `response` — the parsed response object.

```js
document.addEventListener('freeform-ajax-success', (event) => {
  if (!event.response.finished) return;

  console.log('Submission completed:', event.response.submissionId);
});
```

When the form's success behavior is a redirect, this event fires before Freeform redirects. Calling `event.preventDefault()` stops that automatic redirect.

For other success behaviors, Freeform processes the form HTML, reset, and success banner before dispatching this event. Preventing the event does not undo those actions.

#### Custom Return URL

Configure redirects in the form builder whenever possible. To redirect a specific form using custom JavaScript, check that the submission is finished and a return URL is available:

```js
const form = document.getElementById('my-form');

form.addEventListener('freeform-ajax-success', (event) => {
  const { finished, returnUrl } = event.response;

  if (finished && returnUrl) {
    window.location.href = returnUrl;
  }
});
```

See [AJAX Forms](../templates/ajax.mdx) for examples of configuring the return URL and overriding the form builder's success behavior.

:::info
Configure success messages in the form builder. Use plugin options for runtime overrides, or `freeform-render-success` when you need custom success markup or positioning.
:::

### After an AJAX Error: `freeform-ajax-error`

Fires when an AJAX submission returns validation errors or encounters a request failure.

#### Additional Properties

- `request` — the request associated with the failure.
- `response` — the parsed validation response, or error information for a request failure.
- `errors` — field handles mapped to arrays of validation messages, when available.
- `formErrors` — an array of form-level validation messages, when available.

Request failures may not include `errors` or `formErrors`, so check for them before accessing their contents.

```js
document.addEventListener('freeform-ajax-error', (event) => {
  console.log('Field errors:', event.errors || {});
  console.log('Form errors:', event.formErrors || []);
  console.log('Response:', event.response);
});
```

Calling `event.preventDefault()` on this event does not suppress Freeform's default validation feedback. Use `freeform-render-field-errors` or `freeform-render-form-errors` to customize rendering.

:::info
In Freeform 5.17+, compatible formatting templates provide styling for the default AJAX error renderer. JavaScript overrides remain available when additional customization is needed.
:::

### After Processing an AJAX Response: `freeform-ajax-after-submit`

Fires after Freeform processes an HTTP 200 AJAX response and updates the form payload. It can follow a successful response, validation errors, or pending submission actions.

Use it for follow-up tasks that should run after normal response processing.

#### Additional Properties

- `data` — the submitted `FormData`.
- `request` — the `XMLHttpRequest` used for the submission.
- `response` — the parsed response object.

This event is not cancelable.

```js
document.addEventListener('freeform-ajax-after-submit', (event) => {
  console.log('AJAX response processed:', event.response);
});
```

:::info
This event does not fire for every submission attempt. Request failures, redirects, and canceled response processing can bypass it.

Use `freeform-ajax-error` to handle request failures, and `freeform-ajax-success` with a `finished` check to identify completed submissions.
:::

### After a Failed or Canceled Submission: `freeform-after-failed-submit`

Fires when Freeform reports a stopped or unsuccessful submission, including:

- A `freeform-on-submit` listener prevents submission.
- A submission callback returns `false`.
- An AJAX response contains validation errors.

Use it to restore custom interface state after these outcomes. It has no additional properties beyond `form` and `freeform`, and is not cancelable.

```js
document.addEventListener('freeform-after-failed-submit', (event) => {
  console.log('Submission stopped or validation failed:', event.form);
});
```

This event is not a notification for every possible request failure. Use `freeform-ajax-error` when you need the validation or request-error details.

### Rendering Success Messages: `freeform-render-success`

Fires before Freeform renders an AJAX success banner.

This event is optional. Configure messages in the form builder and use formatting-template styling for the default renderer. Use this event when you need custom markup or positioning.

Call `event.preventDefault()` to replace the built-in renderer.

The following example places the success banner at the bottom of the form while using its configured message and classes:

```js showLineNumbers
document.addEventListener('freeform-render-success', (event) => {
  event.preventDefault();

  const { options } = event.freeform;
  const banner = document.createElement('div');
  const message = document.createElement('p');

  banner.className = options.successClassBanner || '';
  banner.setAttribute('role', 'status');
  banner.setAttribute('data-freeform-ajax-banner', 'success');

  message.textContent = options.successBannerMessage || '';
  banner.appendChild(message);

  event.form.appendChild(banner);
});
```

The `data-freeform-ajax-banner` attribute allows Freeform to remove the custom banner during normal AJAX cleanup.

:::note
If your formatting template already provides a custom success-rendering handler, modify that handler rather than adding another one.
:::

### Rendering Form Errors: `freeform-render-form-errors`

Fires before Freeform renders the AJAX error banner.

In Freeform 5.17+, compatible formatting templates provide styling for the default banner. Use this event when you need custom markup or positioning, and call `event.preventDefault()` to replace the built-in renderer.

#### Additional Property

- `errors` — an array of form-level error messages. It may be empty when validation errors belong only to individual fields.

The following example places the error banner at the bottom of the form. It displays the configured error message followed by any form-level errors:

```js showLineNumbers
document.addEventListener('freeform-render-form-errors', (event) => {
  event.preventDefault();

  const { options } = event.freeform;
  const banner = document.createElement('div');
  const message = document.createElement('p');

  banner.className = options.errorClassBanner || '';
  banner.setAttribute('role', 'alert');
  banner.setAttribute('data-freeform-ajax-banner', 'error');

  message.textContent = options.errorBannerMessage || '';
  banner.appendChild(message);

  const errors = event.errors || [];

  if (errors.length) {
    const list = document.createElement('ul');

    errors.forEach((error) => {
      const item = document.createElement('li');
      item.textContent = error;
      list.appendChild(item);
    });

    banner.appendChild(list);
  }

  event.form.appendChild(banner);
});
```

This replaces only the form-level banner. Field errors continue to use their existing rendering behavior.

If your formatting template already provides a custom form-error renderer, modify that handler instead of adding another one.

### Rendering Field Errors: `freeform-render-field-errors`

Fires before Freeform renders individual field validation errors.

In Freeform 5.17+, the default renderer uses compatible formatting templates' field-error styling and supported error-state classes. It also handles accessibility attributes that connect errors to their inputs.

Listen to this event to inspect errors or perform additional tasks. Call `event.preventDefault()` only when you intend to replace the built-in field-error renderer.

#### Additional Property

- `errors` — an object mapping field handles to arrays of validation messages.

The following example logs field errors while allowing Freeform to display them normally:

```js
document.addEventListener('freeform-render-field-errors', (event) => {
  Object.entries(event.errors || {}).forEach(([handle, messages]) => {
    console.log(`Validation errors for ${handle}:`, messages);
  });
});
```

:::info
If you replace field-error rendering, your implementation must handle the error markup, field styling, accessibility relationships, and cleanup.

For class changes alone, use formatting-template overrides or the relevant [Plugin Options](#plugin-options).
:::

### Removing Success and Error Banner Messages: `freeform-remove-messages`

Fires before Freeform clears existing AJAX messages and error styling, including when it processes a subsequent submission response.

Freeform handles cleanup for its default renderer. Custom banners also participate in this cleanup when they use the appropriate marker:

- `data-freeform-ajax-banner="success"`
- `data-freeform-ajax-banner="error"`

You do not need a separate cleanup handler solely because you changed banner classes or used these markers.

Use this event to remove additional elements created by your custom rendering code. The following example removes elements marked with `data-custom-form-message` while allowing Freeform's normal cleanup to continue:

```js
document.addEventListener('freeform-remove-messages', (event) => {
  event.form
    .querySelectorAll('[data-custom-form-message]')
    .forEach((element) => element.remove());
});
```

This event is cancelable. Call `event.preventDefault()` only when your implementation will replace all of Freeform's default message and error-state cleanup.

### Removing Field Messages: `freeform-remove-field-messages`

Fires before Freeform clears validation feedback for a field, including when its value changes.

The default cleanup removes the field's error messages, restores its styling, and clears the accessibility attributes associated with its validation errors.

#### Additional Property

- `field` — the input, select, or textarea element whose feedback is being cleared.

Use this event to clean up additional field-level elements or classes created by your custom code. This example removes a custom class and message blocks marked with `data-custom-field-errors`:

```js
document.addEventListener('freeform-remove-field-messages', (event) => {
  const field = event.field;
  const container = field.closest('[data-field-container]');

  field.classList.remove('my-custom-error-class');

  container
    ?.querySelectorAll('[data-custom-field-errors]')
    .forEach((element) => element.remove());
});
```

This example supplements Freeform's cleanup without preventing it.

Call `event.preventDefault()` only when replacing the default field cleanup. Your implementation must then remove the relevant error markup, restore field styling, and update accessibility attributes while preserving links to instructions or other descriptions.

## Plugin Options

Use plugin options to override settings during the `freeform-ready` event. Most forms can use their form-builder settings and formatting-template styles without additional JavaScript.

Listen on `document` to apply overrides to all forms, or on a specific form element to target only that form.

```js
document.addEventListener('freeform-ready', (event) => {
  event.options.successBannerMessage = 'Thank you! Your form was submitted.';
  event.options.errorBannerMessage = 'Please review your entries and try again.';
});
```

:::info
Success and error messages can also be configured and translated in the form builder. JavaScript message overrides take precedence over those configured messages.
:::

### Submission and Validation

| Option | Type | Description |
|---|---|---|
| `ajax` | `boolean` | Enables or disables built-in AJAX submission handling. Normally controlled by **Use AJAX** in the form builder. |
| `disableSubmit` | `boolean` | Disables submit buttons while Freeform processes a submission, then enables them again when processing ends. |
| `disableReset` | `boolean` | Prevents Freeform from resetting field values after a completed, successful AJAX submission. |
| `skipHtmlReload` | `boolean` | Prevents Freeform from replacing the form's contents with HTML returned by an AJAX response. |
| `focusFirstError` | `boolean` | Moves focus to the first visible field with a validation error, or to the error banner when no field can be focused. |
| `autoScroll` | `boolean` | Scrolls to the form after an AJAX response is processed. Successful error focusing takes precedence over this scrolling. |
| `scrollToAnchor` | `boolean` | Scrolls to the form during initialization when enabled. |
| `scrollOffset` | `number` | Adjusts the scrolling position in pixels. Defaults to `0`; a negative value can leave space above the form for a fixed header. |
| `scrollElement` | `Window` or `HTMLElement` | The target used for scrolling. Defaults to `window`. |

`disableReset` and `skipHtmlReload` control different operations. Disabling the reset does not prevent HTML replacement, and skipping HTML replacement does not prevent field resetting.

For custom markup and multi-page considerations, see [AJAX Forms](../templates/ajax.mdx#not-using-a-formatting-template).

### Processing Feedback

| Option | Type | Description |
|---|---|---|
| `showProcessingSpinner` | `boolean` | Enables the submit button's processing indicator. |
| `showProcessingText` | `boolean` | Replaces the submit button's text while the submission is processing. |
| `showProcessingOverlay` | `boolean` | Displays a processing overlay over the form. |
| `processingText` | `string` | The text used for the processing button text and overlay. |

```js
document.addEventListener('freeform-ready', (event) => {
  event.options.showProcessingText = true;
  event.options.showProcessingOverlay = true;
  event.options.processingText = 'Submitting…';
});
```

### Success and Error Messages

| Option | Type | Description |
|---|---|---|
| `successBannerMessage` | `string` | The message displayed by the default AJAX success-banner renderer. |
| `errorBannerMessage` | `string` | The summary message displayed by the default AJAX error-banner renderer. |

These options change the banner messages. They do not replace individual field-validation messages or additional form-level errors.

### Success and Error Styling<Badge type="feature" text="Improved in 5.17+" />

In Freeform 5.17+, the default AJAX renderer uses compatible formatting templates' banner attributes, field-error styling, and supported error-state classes.

JavaScript class overrides remain available. Existing overrides can stay in place; updating to 5.17 does not, by itself, require removing or replacing them.

| Option | Type | Behavior in 5.17+ |
|---|---|---|
| `successClassBanner` | `string` | Overrides the success-banner classes inherited from the formatting template. Without template classes or an override, the fallback is `freeform-form-success`. |
| `errorClassBanner` | `string` | Overrides the error-banner classes inherited from the formatting template. Without template classes or an override, the fallback is `freeform-form-errors`. |
| `errorClassList` | `string` | A value other than `freeform-errors` overrides the field-error block's inherited classes. Leaving this at `freeform-errors` allows template classes to be inherited when a matching rendered error block is available. |
| `errorClassField` | `string` | Adds classes to invalid inputs alongside the formatting template's error-state classes. Defaults to `freeform-has-errors`; it does not replace template classes. |

Class options accept multiple class names separated by spaces:

```js showLineNumbers
document.addEventListener('freeform-ready', (event) => {
  event.options.successClassBanner = 'alert alert-success';
  event.options.errorClassBanner = 'alert alert-danger';
  event.options.errorClassList = 'my-field-errors';
  event.options.errorClassField = 'my-invalid-input';
});
```

:::info
Custom rendering handlers control their own output. If a formatting template or your JavaScript replaces the default renderer, these options affect that output only if the custom handler uses them.

Change the existing handler when necessary rather than adding a second renderer.
:::

### Custom Rendering and Cleanup Callbacks

The following options replace the corresponding built-in rendering or cleanup function:

| Option | Callback | Purpose |
|---|---|---|
| `renderSuccess` | `function()` | Renders the AJAX success banner. |
| `renderFormErrors` | `function(errors)` | Renders the error banner. Receives an array of form-level errors. |
| `renderFieldErrors` | `function(errors)` | Renders field errors. Receives field handles mapped to arrays of validation messages. |
| `removeMessages` | `function()` | Replaces the normal AJAX message and error-state cleanup. |

Freeform binds these callbacks to its plugin instance. Use a regular function if you need to access the instance through `this`.

The corresponding rendering or cleanup event fires before its callback. If an event listener prevents the default behavior, Freeform skips both the option callback and its built-in implementation.

Use these callbacks or the events documented above when you need custom rendering behavior. Class or message changes alone do not require replacing the renderer.

## Stripe Payments Events<Badge type="feature" text="Improved in 5.0+" />

Use `freeform-stripe-appearance` to customize Stripe's Payment Element before Freeform creates it.

The event exposes two option objects:

- `elementOptions` — options passed to `stripe.elements()`, including `appearance`.
- `paymentOptions` — options passed when creating the Payment Element, including `layout`.

Listen on `document` to customize all Stripe payment fields, or on a specific form element to target that form.

:::info
This event bubbles from the Stripe payment field. Unlike Freeform's form events, it does not include `event.form` or `event.freeform`.

If needed, find the containing form with `event.target.closest('form')`. Modify the supplied options to customize initialization; calling `event.preventDefault()` does not stop it.
:::

### `elementOptions.appearance`

Use [Stripe's Appearance API](https://docs.stripe.com/elements/appearance-api) to customize the Payment Element's theme, variables, and supported styling rules.

Common variables include:

| Variable | Description |
|---|---|
| `fontFamily` | Font family used by the Payment Element. |
| `fontSizeBase` | Base font size used to derive other font sizes. |
| `spacingUnit` | Base spacing used throughout the interface. |
| `borderRadius` | Corner radius for inputs, tabs, and other elements. |
| `colorPrimary` | Primary accent color. |
| `colorBackground` | Background color. |
| `colorText` | Text color. |
| `colorDanger` | Error color. |

Use `appearance.rules` for supported Stripe selectors such as `.Input`, `.Label`, and `.Input:focus`.

Stripe supports specific public classes and styling properties. Arbitrary HTML selectors and descendant selectors are not supported. See the [Appearance API rules reference](https://docs.stripe.com/elements/appearance-api#rules) for the available options.

#### Styling Rules

Use `elementOptions.appearance.rules` to style Stripe's supported public classes, states, pseudo-classes, and pseudo-elements.

Examples of supported selectors include:

| Selector | Targets |
|---|---|
| `.Tab`, `.Label`, `.Input` | Tabs, labels, and inputs. |
| `.Tab:focus` | A focused tab. |
| `.Input--invalid`, `.Label--invalid` | Inputs and labels in their invalid state. |
| `.Input::placeholder` | Input placeholder text. |

The following selectors are not supported:

| Selector | Reason |
|---|---|
| `.p-SomePrivateClass` | Private Stripe classes cannot be targeted. |
| `img` | Arbitrary HTML element selectors are not supported. |
| `.Tab .TabLabel` | Descendant selectors are not supported. |
| `.Tab--invalid` | Tabs do not support the `--invalid` state. |

Each class supports specific states and CSS properties. See [Stripe's Appearance API rules reference](https://docs.stripe.com/elements/appearance-api#rules) for the complete list.

### `paymentOptions.layout`

Use `paymentOptions.layout` to configure the Payment Element's layout.

| Property | Description |
|---|---|
| `type` | Selects `tabs` or `accordion`. |
| `defaultCollapsed` | Controls whether the element initially appears collapsed. |
| `radios` | Controls radio indicators in accordion layouts. Stripe currently documents `auto`, `always`, `never`, and `if_multiple`. |
| `spacedAccordionItems` | When `true`, adds space between accordion items. |
| `visibleAccordionItemsCount` | Number of accordion items shown before the “More” control. Set to `0` to show all available items. Stripe's documented default is `5`. |

See [Stripe's Payment Element options](https://docs.stripe.com/js/elements_object/create_payment_element) for the complete reference.

## Autoscroll Events

Customize Freeform's automatic scrolling through the `freeform-ready` event. This is useful when a fixed header obscures the top of the form or your page uses a scrollable container.

| Option | Purpose |
|---|---|
| `scrollOffset` | Adjusts the scroll position in pixels. Defaults to `0`. A negative value leaves space above the form. |
| `scrollElement` | Specifies the window or element to scroll. Defaults to `window`. |

### Adjusting the Scroll Offset

These examples leave 80 pixels above the form to accommodate a fixed header:

<Tabs>
  <TabItem value="scroll-offset-all" label="All Forms" default>
    ```js
    document.addEventListener('freeform-ready', (event) => {
      event.options.scrollOffset = -80;
    });
    ```
  </TabItem>
  <TabItem value="scroll-offset-form" label="Specific Form">
    Place this code after the markup for a form with the ID `my-form`:

    ```js
    const form = document.getElementById('my-form');

    form?.addEventListener('freeform-ready', (event) => {
      event.options.scrollOffset = -80;
    });
    ```
  </TabItem>
</Tabs>

Adjust `-80` to match your header height and the desired spacing.

### Changing the Scroll Target

If your page scrolls inside an element instead of the browser window, use `scrollElement` to select that container:

```js
document.addEventListener('freeform-ready', (event) => {
  const container = document.getElementById('main');

  if (container) {
    event.options.scrollElement = container;
  }
});
```

The selected element must be a scrollable container. Leave the default `window` target when the browser page itself scrolls.

:::info
Changing the offset or target does not enable automatic scrolling. Configure the relevant scrolling settings in Freeform, or use the [Plugin Options](#plugin-options).

When **Focus First Error After Submit** successfully focuses an error, it takes precedence over Freeform's standard AJAX autoscroll.
:::

## Table Field Events

The [Table](../forms/fields/table.mdx#table) field dispatches events when rows are added or removed through Freeform's controls.

Listen on `document` to handle events from all forms, or on a specific form element to target that form. Each event includes `event.form`, `event.freeform`, and `event.table`.

| Event | When it fires | Includes `event.row` |
|---|---|---|
| `freeform-field-table-on-add-row` | Before the new row is inserted. | Yes |
| `freeform-field-table-after-row-added` | After the new row is inserted. | Yes |
| `freeform-field-table-on-remove-row` | Before the row is removed. | Yes |
| `freeform-field-table-after-remove-row` | After the row is removed. | No |

:::info
These events let you customize rows or respond to changes. Calling `event.preventDefault()` does not stop Freeform from adding or removing a row.
:::

### `freeform-field-table-on-add-row`

Fires after Freeform prepares the new row's inputs and default values, but before inserting the row into the table.

Use `event.row` to customize the new row before it appears:

```js
document.addEventListener('freeform-field-table-on-add-row', (event) => {
  event.row.classList.add('my-table-row');
});
```

### `freeform-field-table-after-row-added`

Fires after the new row has been inserted into the table.

Use this event to initialize custom widgets or interact with the row's inputs. This example focuses the first available input:

```js
document.addEventListener('freeform-field-table-after-row-added', (event) => {
  const input = event.row.querySelector(
    'input:not([type="hidden"]):not(:disabled), select:not(:disabled), textarea:not(:disabled)'
  );

  input?.focus();
});
```

### `freeform-field-table-on-remove-row`

Fires immediately before a row is removed.

Use `event.row` to inspect the row or clean up custom widgets attached to it before removal:

```js
document.addEventListener('freeform-field-table-on-remove-row', (event) => {
  console.log('Row about to be removed:', event.row);
});
```

### `freeform-field-table-after-remove-row`

Fires after a row has been removed.

Use `event.table` to inspect the remaining rows or update calculations and other interface elements:

```js
document.addEventListener('freeform-field-table-after-remove-row', (event) => {
  const rows = event.table.querySelectorAll('tbody > tr');

  console.log('Remaining rows:', rows.length);
});
```

:::info
These events describe row additions and removals. Rows already present when the form loads need any custom widget initialization during your normal setup.
:::

## Save & Continue Later Button Events

Use `freeform-save-form-handle-token` to customize what happens after the [Save & Continue Later](../forms/fields/submit-buttons.mdx#save--continue-later) button saves an AJAX form's progress.

The event provides:

- `key` — the key associated with the saved form state.
- `token` — the saved form's session token.
- `url` — the URL Freeform will redirect to after saving.

You can modify `event.url` to change the destination, or call `event.preventDefault()` to stop the automatic redirect and handle the result yourself.

This event is dispatched directly on the form. Attach your listener to that form element.

### Example

Place this example after a form with the ID `my-form`. It replaces the automatic redirect with a confirmation message:

```html
<div id="save-status" role="status" aria-live="polite"></div>

<script>
  const form = document.getElementById('my-form');

  form?.addEventListener('freeform-save-form-handle-token', (event) => {
    const status = document.getElementById('save-status');

    if (!status) return;

    event.preventDefault();
    status.textContent = 'Your progress has been saved.';
  });
</script>
```

Preventing the redirect does not undo the saved progress.

## Conditional Rules Events

Use `freeform-rules-applied` to respond when [Conditional Rules](../forms/conditional-rules.mdx) change a field or button container's visibility.

The event provides:

- `rule` — the rule being applied.
- `target` — the affected field or button container.

This event is dispatched on the affected container and does not bubble. Use a capture listener to receive it at document level:

```js
document.addEventListener(
  'freeform-rules-applied',
  (event) => {
    const container = event.target;
    const visible = !container.hasAttribute('data-hidden');

    console.log('Rule applied:', event.rule);
    console.log('Container visible:', visible);
  },
  { capture: true }
);
```

:::info
This event reports visibility changes after a rule is applied. It does not fire during the initial rule setup or when the container's visibility remains unchanged.

Calling `event.preventDefault()` does not undo the visibility change.
:::

## External Script Loaders<Badge type="feature" text="New in 5.11.5+" />

Freeform provides events for external assets inserted through its JavaScript loading helpers. Use them to customize generated tags before insertion or respond after an asset loads.

These events are dispatched on `document` and expose their properties through `event.detail`.

| Event | When it fires | Properties |
|---|---|---|
| `freeform-script-before-load` | Before the script tag is inserted. | `detail.src`, `detail.script` |
| `freeform-script-after-load` | After the script loads successfully. | `detail.src`, `detail.script` |
| `freeform-stylesheet-before-load` | Before the stylesheet link is inserted. | `detail.href`, `detail.link` |
| `freeform-stylesheet-after-load` | After the stylesheet loads successfully. | `detail.href`, `detail.link` |

### Scripts

This example adds an attribute to Google's reCAPTCHA script tag. Checking the URL's hostname and path allows it to match URLs containing query parameters:

```js
document.addEventListener('freeform-script-before-load', (event) => {
  const { src, script } = event.detail;
  const url = new URL(src, window.location.href);

  if (
    url.hostname === 'www.google.com' &&
    url.pathname === '/recaptcha/api.js'
  ) {
    script.setAttribute('data-custom-attribute', 'value');
  }
});
```

To run code after an external script loads:

```js
document.addEventListener('freeform-script-after-load', (event) => {
  console.log('External script loaded:', event.detail.src);
});
```

### Stylesheets

Customize a generated stylesheet tag before insertion:

```js
document.addEventListener('freeform-stylesheet-before-load', (event) => {
  event.detail.link.setAttribute('data-custom-attribute', 'value');
});
```

To run code after a stylesheet loads:

```js
document.addEventListener('freeform-stylesheet-after-load', (event) => {
  console.log('External stylesheet loaded:', event.detail.href);
});
```

:::info
Register these listeners before Freeform requests the assets. Assets already present in its loader cache do not trigger a new loading cycle.

These events are not cancelable and do not cover every script or stylesheet already included in your page.
:::
