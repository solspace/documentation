# Salesforce CRM<Badge type="pro" text="Pro" /><Badge type="feature" text="Improved in 5.18+" />

Send submissions to Salesforce **Leads**, **Accounts**, **Contacts**,
**Opportunities**, and **Cases**. To create marketing prospects, use
[Salesforce Account Engagement (Pardot)](/craft/freeform/v5/integrations/salesforce-account-engagement-pardot/).

Your Salesforce organization must support API access, and the authorizing user
needs access to the records and fields you map. See
[Salesforce's API access requirements](https://developer.salesforce.com/docs/platform/api-rest/guide/intro-rest-compatible-editions.html).

<span id="setup-instructions" />

## Connect your account

<VerticalStepWrapper>
<StepMarkdown>

Copy Freeform's **OAuth Callback URL**. Follow the app setup instructions below.

</StepMarkdown>
<StepMarkdown>

Enter the app's consumer key as **Client ID** and consumer secret as **Client Secret**.

</StepMarkdown>
<StepMarkdown>

Keep the default **Salesforce login options** unless you use a sandbox or your
administrator specifies a custom login URL.

</StepMarkdown>
<StepMarkdown>

Save the integration and click **Authorize**. Sign in with the Salesforce user
Freeform should use and approve the requested permissions.

</StepMarkdown>
</VerticalStepWrapper>

Existing connections keep their authorization, credentials, and field mappings.

<details className="hidden-heading">
<summary>Set up a Salesforce app</summary>

For a new connection, search for **External Client Apps** in Salesforce Setup
and open the app manager.

<VerticalStepWrapper>
<StepMarkdown>

Create an app for Freeform and enable OAuth.

</StepMarkdown>
<StepMarkdown>

Paste Freeform's exact **OAuth Callback URL** into the callback URL field.

</StepMarkdown>
<StepMarkdown>

Add `api` for API access and `refresh_token` to keep the connection authorized.
Salesforce may show `refresh_token` alongside `offline_access`.

</StepMarkdown>
<StepMarkdown>

Enable the authorization code / web server flow. Keep the client secret and
PKCE requirements enabled.

</StepMarkdown>
<StepMarkdown>

Save the app and copy its consumer key and secret from the OAuth settings
into Freeform.

</StepMarkdown>
</VerticalStepWrapper>

Your organization's policies must allow the authorizing user to access the app.
See [Salesforce's OAuth settings guide](https://help.salesforce.com/s/articleView?id=sf.configure_external_client_app_oauth_settings.htm&language=en_US&type=5).

</details>

<details className="hidden-heading">
<summary>Use an existing Connected App</summary>

You can keep a working **Connected App**. In Salesforce **App Manager**, check
that OAuth is enabled, the callback URL matches Freeform's, and `api` and
`refresh_token` are included. Use the consumer key and secret as **Client ID**
and **Client Secret**.

Use an External Client App for new connections. See
[Salesforce's Connected App guidance](https://help.salesforce.com/s/articleView?id=sf.connected_app_create_api_integration.htm&language=en_US).

</details>

<details className="hidden-heading">
<summary>Choose a Salesforce login server</summary>

Under **Salesforce login options**, choose where to authorize the connection:

- **Standard login:** leave both options off to use `https://login.salesforce.com`.
- **Use Salesforce sandbox login:** use `https://test.salesforce.com`.
- **Use custom Salesforce login URL:** enter a full URL in **Salesforce login URL**,
  such as `https://mycompany.my.salesforce.com`. This overrides the sandbox option.

After authorization, Freeform sends API requests to the Salesforce instance
returned by OAuth.

</details>

## Map your form

<VerticalStepWrapper>
<StepMarkdown>

In the form builder, open **Integrations** and choose **Salesforce CRM** or the
name you gave the connection.

</StepMarkdown>
<StepMarkdown>

Enable the integration and the objects that should receive submissions.
You can use multiple objects on one form.

</StepMarkdown>
<StepMarkdown>

Map your form fields to Salesforce fields and save the form.

</StepMarkdown>
</VerticalStepWrapper>

<details className="hidden-heading">
<summary>Leads and follow-up tasks</summary>

**Map to Leads** creates a Lead from the mapped fields.

- **Update Duplicate Leads** updates a Lead with a matching email address.
- **Assign Lead Owner** applies Salesforce's lead assignment rules.
- **Convert Leads to Contact Tasks for Returning Customers** creates a Task
  instead of a Lead when a Contact has the submitted email address. Set
  **Task Subject** and **Task Due Date**, using a relative date such as `2 days`.

</details>

<details className="hidden-heading">
<summary>Accounts, Contacts, and Opportunities</summary>

**Accounts:** Freeform matches by Account name and updates a match. If no
Account name is mapped, it uses the mapped Contact's first and last name.

**Contacts:** Freeform matches by email, then name. It updates a match or creates
a Contact, linking it to an Account when one was matched or created.

**Opportunities:** Each submission creates a new Opportunity, linked to the
Account when available. Set **Close Date** with a relative date such as `7 days`
and use a **Stage Name** that exists in Salesforce.

</details>

<details className="hidden-heading">
<summary>Cases and support requests</summary>

**Map to Cases** creates a new Case for each submission, even from the same
email address. Cases can be used on their own without other objects.

- Map **Subject**, **Description**, and any supplied contact details. Use
  **SuppliedEmail** for the visitor's email address.
- For **Status**, **Origin**, **Priority**, and custom fields, use values from
  your Salesforce organization, such as `Web` for Origin. Fields with defaults
  can stay unmapped. Include required custom fields and any fields required by record types or validation rules.
- **Apply Case Assignment Rules** is on by default. Turn it off when mapping an
  **Owner ID** directly.
- **Attach Uploaded Files to Cases** links submission uploads to the Case.
- Accounts and Contacts matched or created by this integration are linked
  automatically. Mapped **Account ID** and **Contact ID** values take precedence
  and must be Salesforce record IDs. An email address alone does not look up or
  create a Contact.

The integration does not update existing Cases or synchronize replies.

</details>

<details className="hidden-heading">
<summary id="duplicate-check--update">Duplicate matching and checkbox values</summary>

**Check Contact email address and Account website when checking for Duplicates**
changes Account matching from name to website. Without a website, Freeform uses
the mapped Contact's email domain. Contacts still match by email, then name.

**Append Checkboxes field values** adds mapped selections to existing Account
or Contact values instead of replacing them.

These settings do not prevent new Opportunities or Cases.

</details>

<details className="hidden-heading">
<summary>Uploaded files and field types</summary>

Enable **Attach Uploaded Files** for each object that should receive uploads.

Supported fields include text, email, phone, URLs, picklists, multi-select
picklists, numbers, currency, booleans, dates, and date/times. Reference fields
require Salesforce record IDs. Available fields depend on the authorizing
user's permissions.

</details>

<details className="hidden-heading">
<summary>Troubleshoot authorization</summary>

- Match the Salesforce callback URL exactly to Freeform's **OAuth Callback URL**.
- Use the app's consumer key and secret, not a Salesforce username and password.
- Check API access and the user's permissions for mapped objects and fields.
- Allow the user to access the app and include `api` and `refresh_token` scopes.
- When moving to production, update the callback URL and authorize the
  connection on the production site.

</details>
